# Core runtime.

# Deliberately light. The walk-in test means an assessor has to install this and
# run it on a machine that is not this one, so every dependency here is a
# deliberate choice rather than a transitive convenience. The pipeline reads
# depth maps, fits planes and writes JSON/SVG with no compiled extension beyond
# what these pull in.
numpy>=1.26
Pillow>=10.0
scipy>=1.11

# Analysis and reporting only. Not imported by the capture-to-plan path; used
# for residual plots and the benchmark figures in the technical report. If this
# section is ever folded into the core, that is a regression.
matplotlib>=3.8
pytest>=8.0

# Deliberately absent, and why:
#
#   torch, torchvision    Monocular depth estimation would need these, plus
#                         roughly 2 GB of model weights. It would break the
#                         clean-machine property above, and no metric photo-tier
#                         path could be finished and validated inside the
#                         assessment window regardless, so depending on it would
#                         trade a working pipeline for an unrunnable one.
#   opencv-python         Feature detection and matching for the photo tier.
#                         Same reasoning: a from-scratch numpy matcher would be
#                         materially weaker and would not change the outcome.
#   open3d, pcl, gtsam    Point-cloud and pose-graph optimisation. The measured
#                         drift is random per-frame scatter with no systematic
#                         component (R2 ~ 0.003), so there is no loop-closure
#                         problem for a pose graph to solve. Plane anchoring is
#                         the right primary mechanism and needs none of these.
